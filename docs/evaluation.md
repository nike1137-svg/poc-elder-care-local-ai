## 3. 음성인식(STT) 결과

### 3.1 최종 성능 (채택 설정: whisper-small + 도메인 프롬프트)

| 데이터셋 | 건수 | 성공 | CER 평균 | CER 중앙값 | 지연 평균 | RTF |
|---|---:|---:|---:|---:|---:|---:|
| 합성 돌봄 | 20 | **20/20** | **0.0131** | 0.0000 | 3.05s | 0.38 |
| Zeroth (실제 사람) | 40 | **40/40** | **0.0633** | 0.0572 | 3.75s | 0.34 |

- **전사 실패 0건.** 60건 모두 결과를 냈다
- **중앙값 0.0000** — 합성 코퍼스 20건 중 절반 이상이 완벽 전사
- **RTF 0.34~0.38** — 실시간의 3배 빠르다. S2를 여유 있게 만족

### 3.2 스타일별 — 어르신 발화 특성에서 무너지지 않는가

| 스타일 | 건수 | 평균 CER |
|---|---:|---:|
| noisy (생활 소음) | 2 | **0.0000** |
| pause (문장 중 침묵) | 2 | **0.0000** |
| normal | 11 | 0.0216 |
| slow (느린 발화) | 5 | 0.0259 |

**소음과 침묵에서 오히려 오류가 없었다.** 우려했던 취약점이 실측에서는 나타나지 않았다.
느린 발화가 가장 어려웠지만 그래도 2.6% 수준이다.

### 3.3 실제로 틀린 것들 (합성 코퍼스, 튜닝 전 기준)

| id | 정답 | 인식 | CER |
|---|---|---|---:|
| u02 | 무릎이 좀 **시큰거려서** | 무릎이 좀 **식흥거려서** | 0.105 |
| u07 | 그건 안 **빼먹어** | 그건 안 **떼 먹어** | 0.048 |
| u03 | 약은 **어,** 아침에 | 약은 **너** 아침에 | 0.045 |
| u05 | 새벽 **세시**에 | 새벽 **3시**에 | 0.045 |
| u01 | **응** 잘 잤어 | **눈** 잘 잤어 | 0.043 |

읽어낼 것:

- `u02`의 "시큰거려서"는 **도메인 어휘**다. 이 관찰이 프롬프트 튜닝의 출발점이 됐고,
  어휘 목록에 넣은 뒤 개선됐다 ([tuning.md](tuning.md))
- `u05`는 **오인식이 아니라 정규화 인공물**이다. "세시"를 "3시"로 적은 것은
  사람이 보기엔 맞는 전사인데, 고유어 수사를 못 다뤄 오류로 계산됐다
- `u03`의 군말 "어,"를 "너"로 들은 것은 **실제 오류**다. 군말은 이 도메인에서
  의미 있는 신호라 놓치면 아쉽다

### 3.4 모델 크기 비교

| 모델 | CER 평균 | RTF | 적재 | 판정 |
|---|---:|---:|---:|---|
| base | 0.0415 | 0.136 | 8.8s | CER 2배 이상 나쁨 |
| **small** | **0.0184** | **0.380** | **1.5s** | ✅ 채택 |
| medium | 0.0151 | **1.105** | 50.4s | **실시간 초과 → S2 위반** |

`medium`은 CER이 0.33%p 낫지만 **RTF 1.105로 실시간을 넘긴다.**
게다가 `small` + 도메인 프롬프트(**0.0131**)가 `medium` 무튜닝(0.0151)보다
**정확하면서 7배 빠르다.** 튜닝이 모델 크기를 한 단계 이겼다.

### 3.5 하이퍼파라미터 튜닝 효과

| 설정 | 합성 | Zeroth | |
|---|---:|---:|---|
| 튜닝 전 | 0.0184 | 0.0658 | 기준 |
| **채택 (도메인 프롬프트)** | **0.0131 (-28.8%)** | **0.0633 (-3.8%)** | ✅ 양쪽 개선 |

## 4. 특이사항 추출 결과

### 4.1 수치

| 기준 | 재현율 | 정밀도 | F1 |
|---|---:|---:|---:|
| 정답 전사문 | **1.000** | 0.962 | 0.980 |
| **STT 출력** (실제 파이프라인) | **1.000** | 0.962 | 0.980 |

유형별 재현율은 건강·복약·식사·수면·기분 **전부 1.000**이다.

전사 오류로 인한 손실이 **0**인 점이 눈에 띈다.
처음에는 0.960으로 떨어졌었는데, 원인이 ASR의 구두점 오류였고
이를 수정해 회복했다 ([failure-cases.md](failure-cases.md) §5).

### 4.2 ⚠️ 이 수치를 그대로 믿으면 안 된다

**대본을 쓴 사람과 추출 규칙을 쓴 사람이 같다.**
어떤 문장이 들어올지 알면서 규칙을 만들었으니 잘 맞는 게 당연하다.
전형적인 과적합이고, **처음 보는 발화에서는 이 점수가 나오지 않는다.**

정밀도를 함께 보고하는 이유가 이것이다 — "아무거나 다 뽑아서 재현율만 올리는" 것을
걸러내기 위해서다. 오탐은 1건이었다.

의미 있게 읽을 수 있는 것은 **"규칙이 의도대로 동작한다"**까지이고,
**"처음 보는 표현에서도 통한다"**는 아니다.

## 6. 기준선 비교 — 기존 방식을 실제로 돌렸다

합성 코퍼스 20건에 **기존 방식(클라우드 LLM 프롬프트 전사)**을 그대로 돌렸다.
프롬프트는 실서비스 원문을 그대로 썼다.

### 6.1 결과 — 두 번 측정했다

같은 음성 20건, 같은 프롬프트, `temperature=0`. 하루 간격으로 두 번 돌렸다.

| 항목 | 기존 1차 (8/12) | 기존 2차 (8/13) | 개선안 (로컬) |
|---|---:|---:|---:|
| **CER 평균** | **0.0075** | **0.0185** | **0.0131** |
| CER 중앙값 | 0.0000 | 0.0000 | 0.0000 |
| **성공 건수** | 19/20 | 19/20 | **20/20** |
| 실패 원인 | 호출 한도(429) | 네트워크 타임아웃 | — |
| **지연 평균** | 13.17초 | 15.53초 | **3.05초** |
| **실시간 대비(RTF)** | 1.82 (초과) | 2.13 (초과) | **0.38** |
| **외부 전송** | 19건 | 19건 | **0건** |
| **비용** | 약 3.04원 | 약 3.08원 | **0원** |
| **재실행 시 동일한가** | — | **아니오** | **예** (해시 일치) |

> 저장된 결과 파일(`results/gemini_gemini-flash-latest_synthetic.json`)은 **2차 실행**의 것이다.
> 1차 결과 파일은 재실행 과정에서 덮어써져 남아 있지 않다(§6.6 ③).

### 6.2 가장 중요한 발견 — 클라우드 기준선은 재현되지 않는다

**CER이 0.0075 → 0.0185 로 2.5배 벌어졌다.** 1차에서는 클라우드가 개선안을 이겼고(0.0075 < 0.0131),
2차에서는 졌다(0.0185 > 0.0131). **어느 쪽을 인용하느냐로 결론이 뒤집힌다.**

달라진 전사문은 이랬다.

| 발화 | 정답 | 1차 | 2차 |
|---|---|---|---|
| u05 | 잠을 **설쳤어** | 설쳤어 ✅ | **설치었어** ❌ |
| u19 | **보냈더라고** | 보냈더라고 ✅ | **보내왔더라고** ❌ |
| u20 | 기침이 좀 **나.** | 나 ✅ | **나고** ❌ |

**원인 후보는 둘이었다.**

1. **모델이 바뀌었다** — 기준선에 쓴 `gemini-flash-latest` 는 **별칭**이다.
   제공자가 가리키는 실제 모델을 바꾸면 이쪽은 알 방법이 없다.
2. **같은 모델이 다르게 답했다** — `temperature=0` 이어도 LLM 출력은 완전히 결정적이지 않다.

#### 가려보기 위한 추가 실험

둘을 구분하는 방법이 있다. **버전이 고정된 모델**(`gemini-3.6-flash`)을
**몇 분 간격으로** 두 번 돌려보는 것이다. 그 사이에 모델이 바뀔 리는 없으므로,
결과가 달라지면 2번(비결정성), 같으면 1번(모델 교체) 쪽이다.

| 실험 | 결과 |
|---|---|
| `gemini-3.6-flash` 1회차 vs 2회차 (수 분 간격) | 성공한 **4건 전부 전사문 동일** |
| `gemini-3.6-flash` 3회차 (u05) | `설쳤어` — 1·2회차와 동일 |
| `gemini-flash-latest` 어제 vs 오늘 | **다름** (`설쳤어` → `설치었어`) |

**버전 고정 모델은 같은 답을 냈고, 별칭은 날짜에 따라 다른 답을 냈다.**
→ **"별칭이 가리키는 모델이 바뀌었다"는 가설에 무게가 실린다.**

⚠️ 다만 단정하지 않는다. 무료 티어 한도(모델당 하루 20건) 때문에
비교할 수 있었던 것이 **5건 중 성공한 4건뿐**이다. 표본이 작다.

#### 그래서 고친 것

원인 후보를 처음부터 가릴 수 있었어야 했다. **응답에 담겨 오는 `modelVersion` 을
기록하지 않은 것**이 문제였다. 어느 모델이 답했는지 안 남겨두면 나중에 대조할 방법이 없다.

- `model_version` 과 `response_id` 를 저장하도록 고쳤다 (`src/stt_gemini.py`)
- 벤치마크에는 **별칭 대신 버전 고정 이름**을 쓰는 편이 낫다는 것도 확인했다

> 이건 클라우드 API를 벤치마크에 쓸 때의 일반 교훈이기도 하다.
> `-latest` 가 붙은 이름은 **편하지만 재현되지 않는다.**

### 6.3 그래서 무엇을 말할 수 있나

**정확도 우열은 단정하지 않는다.** 두 번 재서 한 번은 이기고 한 번은 졌다.
표본 20건에 이 정도 변동이면 "어느 쪽이 정확하다"는 결론을 내리기에 부족하다.

대신 **더 중요한 차이가 드러났다.**

| | 기존 (클라우드) | 개선안 (로컬) |
|---|---|---|
| 같은 입력에 같은 출력 | **아니오** | **예** (해시 일치 확인) |
| 성능을 하나의 값으로 말할 수 있나 | **아니오** | **예** |
| 어떤 모델이 답했는지 아는가 | 별칭이라 **모름** | 파일로 고정 |
| 제공자가 바꾸면 | **통보 없이 바뀜** | 내가 안 바꾸면 안 바뀜 |

돌봄 서비스에서 이건 사소하지 않다. **"어제는 알아듣던 말을 오늘은 못 알아듣는"** 일이
생겨도 원인을 짚을 수가 없다. 로컬 모델은 내가 바꾸지 않는 한 어제와 같이 동작한다.

### 6.4 그 외 읽어낼 것

**① 두 번 모두 실시간을 넘겼다.** RTF 1.82와 2.13. 7초 음성에 13~15초가 걸린 셈이다.
네트워크 왕복과 서버 대기가 섞여 있다. 성공 기준 S2를 **기존 방식은 두 번 다 만족하지 못했다.**

**② 두 번 모두 1건씩 실패했다.** 1차는 호출 한도(429), 2차는 네트워크 타임아웃(120초).
원인은 달랐지만 결과는 같다 — **네트워크 너머에 있는 것은 언제든 실패한다.**
로컬 방식은 두 번 다 20/20이었다.

**③ 같은 단어에서 같이 틀렸다.**

| | 텍스트 |
|---|---|
| 정답 | 오늘은 무릎이 좀 **시큰거려서** 산책은 못 나갔다 |
| 기존 (클라우드) | 오늘은 무릎이 좀 **시끈거려서** 산책은 못 나갔다 |
| 개선안 (로컬) | 오늘은 무릎이 좀 **식흥거려서** 산책은 못 나갔다 |

둘 다 틀렸다. **"시큰거리다"는 이 도메인 어휘라서 범용 모델이 약한 것**이고,
바로 이 관찰이 도메인 프롬프트 튜닝의 출발점이 됐다 ([tuning.md](tuning.md)).
클라우드로 옮긴다고 해결되는 문제가 아니었다는 뜻이다.

**② 그러나 실시간을 넘겼다.** 기존 방식의 RTF는 **1.82**로,
7초짜리 음성을 처리하는 데 12초 넘게 걸린 셈이다. 네트워크 왕복과 서버 대기가 섞여 있다.
성공 기준 S2(실시간 1배속 이내)를 **기존 방식은 만족하지 못한다.**

**③ 기존 방식은 1건이 실패했다.** 무료 티어 호출 한도(429)에 걸렸다.
로컬 방식은 20건 전건 성공했다. **네트워크 너머에 있는 것은 언제든 실패할 수 있다.**

**④ 같은 단어에서 같이 틀렸다.**

| | 텍스트 |
|---|---|
| 정답 | 오늘은 무릎이 좀 **시큰거려서** 산책은 못 나갔다 |
| 기존 (클라우드) | 오늘은 무릎이 좀 **시끈거려서** 산책은 못 나갔다 |
| 개선안 (로컬) | 오늘은 무릎이 좀 **식흥거려서** 산책은 못 나갔다 |

둘 다 틀렸다. **"시큰거리다"는 이 도메인 어휘라서 범용 모델이 약한 것**이고,
바로 이 관찰이 도메인 프롬프트 튜닝의 출발점이 됐다 ([tuning.md](tuning.md)).
클라우드로 옮긴다고 해결되는 문제가 아니었다는 뜻이다.

### 6.5 그래서 어떻게 판단하는가

정확도는 두 번 재서 한 번씩 나눠 가졌다. 그런데 이 도메인의 요구는 정확도 하나가 아니다.

| 요구 | 기존 | 개선안 |
|---|:-:|:-:|
| 음성이 외부로 나가지 않을 것 (1순위) | ❌ | ✅ |
| 실시간 이내 처리 | ❌ (1.82 / 2.13) | ✅ (0.38) |
| 비용 0원 | ❌ | ✅ |
| **같은 입력에 같은 결과** | ❌ | ✅ |
| 정확도 | △ (0.0075~0.0185) | △ (0.0131) |

**1순위 요구를 만족하지 못하는 후보는 나머지가 아무리 좋아도 탈락**이라고
[model-selection.md](model-selection.md) §1에서 못박았다. 그 기준이 지금도 유효하다.

정확도 차이는 두 번의 측정 어느 쪽을 보든 **1%p 미만**이다.
7초 발화 한 건에 약 30자가 들어가므로, 대략 **발화 수백 건당 한 글자 수준**의 차이다.
그 대가로 얻는 것이 "가족의 대화가 집 밖으로 나가지 않는다"라면, 이 교환은 성립한다.

### 6.6 ⚠️ 이 측정의 한계 — 정직하게

**① 실서비스와 같은 모델이 아니다.** 실서비스는 `gemini-2.5-flash`를 쓰는데,
측정 시점에 이 모델은 **신규 사용자에게 더 이상 제공되지 않았다**(404).
그래서 현행 flash 계열 별칭(`gemini-flash-latest`)으로 대체했다.

> 이건 한계이면서 동시에 **개선의 근거**이기도 하다.
> 문제 정의서에 "어차피 한 번은 갈아타야 한다"고 적었는데,
> 그게 이미 현실이 되어 있었다.
>
> 그리고 §6.2에서 보듯 **별칭을 쓴 것 자체가 재현성을 해쳤다.**
> 벤치마크용으로 다시 잡는다면 `gemini-3.6-flash` 처럼 **버전이 고정된 이름**을 써야 한다.

**② 지연시간은 모델 속도가 아니다.** 기존 방식의 13~15초에는 네트워크 왕복,
서버 큐 대기, 무료 티어 우선순위가 섞여 있다. 유료 티어라면 더 빠를 수 있다.
**"클라우드가 느리다"가 아니라 "이 조건에서 이렇게 나왔다"로 읽어야 한다.**

**③ 1차 측정의 결과 JSON이 없다.** 1차 수치(0.0075)는 실측값이지만,
측정 직후 조건을 바꿔 재실행하는 과정에서 **파일이 덮어써졌고**
그때는 이미 무료 할당량이 소진되어 재생성하지 못했다.
저장소에 있는 것은 **2차 측정(0.0185)의 파일**이다.

같은 일이 반복되지 않도록 `src/evaluate.py` 가 **기존 결과를 덮어쓰기 전에
백업하도록** 고쳤다.

> ### ⚠️ 재현하려는 사람에게 — 무료 티어는 하루 20건이다
>
> 재생성을 시도하다 알아낸 사실이다. 429 응답 본문을 끝까지 열어보니 이렇게 나왔다.
>
> ```
> quotaId: GenerateRequestsPerDayPerProjectPerModel-FreeTier
> quotaValue: 20
> ```
>
> **무료 티어는 하루 20건**이고, 이 평가 코퍼스가 정확히 20건이다.
> 즉 **하루에 딱 한 번만 완주할 수 있고, 연결 테스트 한 번이라도 미리 하면 그만큼 모자란다.**
> 초기화 시점은 태평양 자정(한국 시간 오후 4~5시)이다.
>
> 그래서 재현할 때는 이렇게 해야 한다.
>
> - 테스트 호출을 따로 하지 말 것 (한 건이 아깝다)
> - 모델을 바꿔도 소용없을 수 있다 — 프로젝트 단위로도 걸린다
> - 실패하면 다음 날 다시
>
> 이 제약 자체가 이 PoC의 논거이기도 하다.
> **클라우드에 의존하면 내가 언제 몇 번 쓸 수 있는지를 남이 정한다.**
> 로컬 모델에는 이런 한도가 없다 — 60건이든 600건이든 원할 때 돌린다.

할당량이 회복된 뒤 아래 한 줄이면 결과 JSON이 만들어진다.

```bash
python src/evaluate.py --backend gemini --dataset synthetic
```

**④ 표본이 20건이다.** 이 규모에서 1%p 안팎의 CER 차이는 표본 오차와 구분되지 않는다.
§6.2의 실행 간 변동(0.0075↔0.0185)이 그 증거이기도 하다.

### 왜 무료 티어를 써도 되는가

실서비스는 무료 티어를 못 쓴다. 입력이 모델 학습에 활용될 수 있는데
가족의 실제 대화이기 때문이다.

그런데 **이 PoC의 평가 데이터는 전량 창작 합성 대본**이라 그 제약이 걸리지 않는다.
덕분에 무료로 기준선을 재현할 수 있고, 채점자도 무료 키만으로 재현할 수 있다.

> 바로 이 제약의 존재 자체가 이번 개선의 핵심 동기다.
> "실데이터라 무료 티어를 못 쓴다"는 사실이 "그럼 로컬로 내리자"로 이어졌다.

## 7. 이미지 파이프라인 결과

음성과 같은 개선을 사진에도 적용했다. 온담이에는 이미 사진 인식 기능이 있고,
그 처리 역시 클라우드 범용 LLM이 맡고 있다.

### 7.1 알약 세기 (복약 확인)

정답을 아는 벤치마크로 측정했다. 배경은 생성 이미지, 알약은 개수를 정해 합성했다.

| 이미지 | 정답 | 예측 | 오차 |
|---|---:|---:|---:|
| bench_00 (대조군) | 0 | **0** | 0 |
| bench_01 | 1 | **1** | 0 |
| bench_02 | 3 | **3** | 0 |
| bench_03 | 6 | 7 | +1 |
| bench_04 | 10 | **10** | 0 |
| bench_05 | 15 | **15** | 0 |
| bench_06 | 24 | 25 | +1 |

| 지표 | 값 |
|---|---:|
| 정확히 맞춤 | **5/7** |
| ±1개 이내 | **7/7** |
| 평균 절대 오차 | **0.29개** |
| 평균 상대 오차 | **3.0%** |
| 처리 시간 | 0.3초 내외 |

**대조군(빈 테이블)이 0개로 나온 것이 중요하다** — 배경만으로 오검출이 없다.

> 처음 측정에서는 상대 오차 24.0%였다. 원인은 모델이 아니라 **오염된 배경 데이터**였다
> ([failure-cases.md](failure-cases.md) §6).

⚠️ 이 수치는 **떨어뜨려 놓은 알약** 기준이다. 실제로는 겹쳐 쏟아지는 경우가 많고,
그때 성능은 측정하지 못했다.

### 7.2 인물 마스킹 (프라이버시)

| 이미지 | 탐지 인물 | YOLO | SAM | 외부 전송 |
|---|---:|---:|---:|---:|
| person_01 | 1명 | 0.141s | 1.616s | 0 |
| person_02 | 2명 | 0.147s | 1.792s | 0 |
| person_03 | 1명 | 0.084s | 1.459s | 0 |

**처음에는 가우시안 블러를 썼는데 실패했다** — 블러를 걸었는데도 얼굴을 알아볼 수 있었다.
모자이크로 바꾸고 블록 크기를 인물 크기에 비례시켜 해결했다
([failure-cases.md](failure-cases.md), [model-selection.md](model-selection.md)).

### 7.3 모델 배치에서 부딪힌 문제

처음에는 알약 세기에도 YOLO를 쓰려 했으나, **YOLO11n은 COCO 사전학습이고
COCO 80개 클래스에 '알약'이 없다.** 파인튜닝하려면 라벨링된 약 사진이 필요한데
그 데이터가 없다.

그래서 역할을 나눴다.

| 모델 | 맡은 일 | 이유 |
|---|---|---|
| YOLO11n | `person` 탐지 | COCO에 있는 클래스. 여기선 제 실력을 낸다 |
| MobileSAM | 인물 윤곽 정밀 분할 | 박스만으로 가리면 배경까지 뭉개진다 |
| FastSAM | 알약 자동 분할 | 클래스를 몰라도 '덩어리'를 나눈다 |

## 8. 음성 생성(TTS) 결과

실서비스의 TTS(`edge-tts`)는 로컬 프로세스로 떠 있지만 **합성은 외부에서 일어난다.**
piper로 바꾸면 음성 루프 전체가 집 안에서 닫힌다.

| 항목 | edge-tts (기존) | piper (개선) |
|---|---|---|
| 합성 위치 | 외부 (MS) | **로컬** |
| 외부 전송 | 있음 | **없음** |
| 인터넷 | 필요 | **불필요** |
| 모델 크기 | — | 61MB |
| 모델 적재 | — | 0.85초 |
| 합성 속도 | — | **0.29초** (4.8초 분량) |

### 왕복 검증

piper로 합성한 음성을 Whisper로 되받아 적었더니 **글자 하나 안 틀리고 일치**했다.

```
원문: 어머님, 오늘은 무릎이 아프시다고 하셨네요. 확인이 필요합니다.
전사: 어머님, 오늘은 무릎이 아프시다고 하셨네요. 확인이 필요합니다.
```

실사용에서는 특이사항 리포트(17~19초 분량)를 **1초 안에** 합성한다.

## 9. 이미지 생성(Diffusion) 결과

실사진을 저장소에 넣지 않기 위해 **평가용 이미지 자체를 생성**했다.
음성에서 대본을 TTS로 합성한 것과 같은 논리다.

| 항목 | 값 |
|---|---|
| 모델 | SD-Turbo (로컬 CPU) |
| 생성 시간 | 1스텝 15.5초 / 2스텝 20.2초 |
| 메모리 | 6.0GB (가용 9.1GB) |
| 생성 매수 | 10장 (알약 3 · 인물 3 · 회상 3 · 배경 1) |
| 외부 전송 | **0건** |

회상 이미지는 회상요법용으로도 쓴다. 회상 발화를 감지했을 때만 생성하며,
**발화 원문을 프롬프트에 넣지 않고** 미리 정해둔 안전한 장면 목록에서만 고른다.

```
음성(m4a) → [VAD 관문] → [Whisper 전사] → [특이사항 추출] → [piper 음성 리포트]
```

## 11. 결론

### 달성한 것

- 로컬 Whisper가 GPU 없는 환경에서 **실시간의 3배 속도**로 동작
- 어르신 발화 특성(느린 말·침묵·소음)에서 **무너지지 않음**
- 전사 실패 **0건** (60건 전건 성공)
- 학습 없이 **CER 28.8% 개선**, 교차 검증으로 과적합 설정을 걸러냄
- 외부 전송 **0건**, 비용 **0원** — 구조적 보장
- 나쁜 입력에서 **환각 0건**, 실패를 원인별로 분류
- 5개 모델 전부 로컬 CPU에서 동작

### 달성하지 못한 것

- **기존 방식과의 직접 비교 (S1)** — API 키 미설정 (§6)
- 실제 어르신 음성에서의 성능 — 합성 데이터의 한계
- 겹친 알약 세기 정확도 — 정답 데이터 없음
- 처음 보는 표현에서의 특이사항 추출 성능 — 과적합

### 한 줄로

> **교체를 검토할 근거는 만들어졌다. 교체를 확정하려면 §6의 기준선 측정이 남았다.**

한계와 다음 단계는 [limitations.md](limitations.md),
실서비스 도입 계획은 [adoption-plan.md](adoption-plan.md).
