# 하이퍼파라미터 최적화 — 학습 없이 도메인 성능 끌어올리기

- **작성일**: 2026-08-12
- **결론**: 도메인 어휘 프롬프트로 **CER 28.8% 개선** (0.0184 → 0.0131)
- **채택 설정**: `initial_prompt = 도메인 어휘 16개`, `beam_size = 5`
- **재현**: `python src/tune_whisper.py --dataset synthetic`

---

## 1. 왜 파인튜닝이 아니라 하이퍼파라미터인가

과제 안내에는 "파인튜닝이나 하이퍼파라미터 조정으로 내 도메인 데이터에 맞춰
성능을 끌어올려보세요"라고 되어 있다. 둘 중 **파인튜닝은 이 프로젝트에서 불가능**하다.

파인튜닝하려면 도메인 음성 + 정답 전사문 쌍이 필요한데,
그 데이터가 바로 **이 프로젝트가 쓰지 않기로 한 실사용자 음성**이다
([problem-statement.md](problem-statement.md) §0). 순환 문제다.

그래서 **학습 없이 도메인에 적응시키는 방법**을 찾았다.

### Whisper의 `initial_prompt`

Whisper는 디코딩 시작 전에 텍스트를 넣어줄 수 있다. 모델은 이것을
**"바로 앞에 나온 문맥"**으로 취급해, 이어질 말을 그 방향으로 예측한다.

즉 `"혈압약, 경로당, 무릎…"`을 미리 흘려두면
비슷한 발음 후보 중 이 어휘들을 고를 확률이 올라간다.

- 학습 시간 **0**
- 추가 비용 **0**
- 모델 파일 변경 **없음**
- 언제든 되돌릴 수 있음

파인튜닝의 값싼 대안이면서, 이 도메인에서는 실제로 통했다.

## 2. 무엇을 시험했나

| 설정 | 내용 |
|---|---|
| `baseline` | 튜닝 전 (beam=5, VAD 끔, 프롬프트 없음) |
| `prompt_short` | 도메인 어휘 5개 |
| `prompt_full` | 도메인 어휘 16개 |
| `prompt_sentence` | 문장형 프롬프트 |
| `beam1` | 탐색 폭 1 (탐욕적 디코딩) |
| `beam10` | 탐색 폭 10 |
| `vad_on` | 침묵 제거 켬 |
| `cond_prev` | 앞 문맥 참조 켬 |
| `prompt_full_beam1` | 어휘 16개 + 탐색 폭 1 |
| `prompt_full_beam10` | 어휘 16개 + 탐색 폭 10 |

### 도메인 어휘 16개

```
혈압약, 당뇨약, 경로당, 무릎, 허리, 시큰거리다, 쑤시다, 어지럽다,
깜빡깜빡, 입맛, 된장찌개, 김장, 잠을 설치다, 뒤척이다, 적적하다, 손주
```

> 이것은 **어휘 목록**이지 대화 내용이 아니다. 개인정보가 들어가지 않는다.

## 3. 결과 ① — 합성 돌봄 코퍼스 (20건)

| 설정 | CER 평균 | 개선율 | 지연 |
|---|---:|---:|---:|
| **prompt_full_beam1** | **0.0108** | **-41.3%** | 2.57s |
| prompt_full_beam10 | 0.0108 | -41.3% | 3.50s |
| **prompt_full** | **0.0131** | **-28.8%** | 3.05s |
| prompt_short | 0.0161 | -12.5% | 2.95s |
| prompt_sentence | 0.0161 | -12.5% | 2.88s |
| beam1 | 0.0162 | -12.0% | 2.54s |
| baseline | 0.0184 | — | 2.89s |
| beam10 | 0.0184 | 0.0% | 2.90s |
| vad_on | 0.0184 | 0.0% | 2.73s |
| cond_prev | 0.0184 | 0.0% | 2.77s |

읽어낼 것 세 가지.

1. **어휘가 많을수록 좋았다.** 5개(-12.5%) < 16개(-28.8%). 나열형이 문장형보다 나았다
2. **탐색 폭을 넓혀도 소용없었다.** beam10은 baseline과 동일. 이 도메인의 오류는
   "탐색이 부족해서"가 아니라 "어휘를 몰라서" 생긴 것이다
3. **VAD와 앞 문맥 참조는 아무 효과가 없었다.** 짧은 단발 메시지라 참조할 앞 문맥이 없다

여기까지만 보면 `prompt_full_beam1`(-41.3%)을 골라야 한다. **그런데 골라선 안 됐다.**

## 4. 결과 ② — 공개 데이터셋 교차 검증 (Zeroth-Korean 40건)

같은 20건으로 튜닝하고 같은 20건으로 보고하면 과적합이다.
그래서 **실제 사람이 읽은 공개 데이터셋**에 그대로 돌려봤다.

| 설정 | 합성(돌봄) | Zeroth(뉴스, 실제 사람) | 판정 |
|---|---:|---:|---|
| baseline | 0.0184 | 0.0658 | 기준 |
| **prompt_full** | **0.0131 (-28.8%)** | **0.0633 (-3.8%)** | ✅ **양쪽 다 개선** |
| beam1 | 0.0162 (-12.0%) | 0.0723 (**+9.9%**) | ❌ 실제 음성에서 악화 |
| prompt_full_beam1 | 0.0108 (-41.3%) | 0.0794 (**+20.7%**) | ❌ **1등 → 꼴찌** |

### 합성 데이터 1등이 실제 음성에서 꼴찌가 됐다

`prompt_full_beam1`은 합성 코퍼스에서 가장 좋았지만,
실제 사람 음성에서는 **기준선보다 20.7% 나빴다.**

범인은 `beam1`(탐욕적 디코딩)이다.

- 탐욕적 디코딩은 매 단계에서 **가장 그럴듯한 후보 하나만** 잡고 간다
- 합성 TTS 음성은 깨끗해서 첫 후보가 대체로 맞다 → 문제없다
- 실제 사람 발화는 흐릿한 구간이 있어 **첫 후보가 틀릴 때가 있다**
- 한 번 틀리면 되돌아갈 길이 없어 뒤가 통째로 무너진다

`beam_size=5`는 후보를 여러 개 들고 가다가 나중에 고르므로 이런 붕괴를 막는다.

> **합성 데이터만 보고 결정했다면, 실서비스를 20% 악화시킬 설정을 골랐을 것이다.**
> 교차 검증이 없었다면 이 사실을 몰랐다.

## 5. 채택 결정

### `prompt_full` (도메인 어휘 16개 + `beam_size=5`)

**두 데이터셋 모두에서 개선된 유일한 설정**이기 때문이다.

| | 합성(돌봄) | Zeroth(뉴스) |
|---|---:|---:|
| 개선율 | **-28.8%** | **-3.8%** |

Zeroth에서 개선폭이 작은 것은 당연하다 — 돌봄 어휘를 넣었는데
뉴스 낭독체에 도움이 될 이유가 없다. **작게나마 개선됐고, 무엇보다 악화되지 않았다**는 게 핵심이다.

이 설정은 `src/stt_whisper.py`의 `DOMAIN_PROMPT`로 기본값에 반영되어 있다.
`WhisperBackend(initial_prompt=None)`으로 언제든 튜닝 전 상태로 되돌릴 수 있다.

## 6. 공짜가 아니었다 — 발견된 부작용

도메인 프롬프트를 켠 뒤 강건성 테스트를 다시 돌리자
**한국어가 아닌 입력에서 거동이 나빠졌다.**

| | 프롬프트 없음 | 프롬프트 켬 (채택) |
|---|---|---|
| 영어 발화 입력 | `안녕하세요,This is a test sentence in English, not Korean` | `안녕하세요, 한국인은 영어로 말하는 것입니다` |

원문을 그런대로 옮기던 것이, **없는 한국어 문장을 지어내는** 쪽으로 바뀌었다.
한국어 어휘로 편향시켜 놓았으니 당연한 결과다.

**실서비스 영향은 낮다.** 입력이 항상 한국어이기 때문이다.
그러나 "정확도를 올렸다"가 공짜가 아니었다는 사실은 기록해둔다.
자세한 내용은 [failure-cases.md](failure-cases.md) §4.

## 7. 모델 크기도 함께 비교했다

프롬프트 튜닝과 별개로, 모델 크기 선택도 측정으로 결정했다.

| 모델 | CER 평균 | RTF | 모델 적재 | 판정 |
|---|---:|---:|---:|---|
| base | 0.0415 | 0.136 | 8.8s | CER이 2배 이상 나쁨 |
| **small** | **0.0184** | **0.380** | **1.5s** | ✅ **채택** |
| medium | 0.0151 | **1.105** | 50.4s | CER 0.33%p 개선인데 **실시간 초과** |

`medium`은 더 정확하지만 **RTF가 1을 넘어 성공 기준 S2(실시간 1배속 이내)를 위반**한다.
7초 음성을 처리하는 데 7.7초가 걸리면 대화가 끊긴다.

**`small` + 도메인 프롬프트(CER 0.0131)가 `medium` 무튜닝(CER 0.0151)보다 정확하면서
7배 빠르다.** 튜닝이 모델 크기를 한 단계 이긴 셈이다.

## 8. 재현 방법

```bash
# 합성 코퍼스 전체 스윕 (10개 설정)
python src/tune_whisper.py --dataset synthetic

# 공개 데이터셋 교차 검증 (핵심 4개만)
python src/tune_whisper.py --dataset zeroth --only baseline beam1 prompt_full prompt_full_beam1
```

결과는 `results/hyperparam_sweep_synthetic.json`,
`results/hyperparam_sweep_zeroth.json` 에 저장된다.
